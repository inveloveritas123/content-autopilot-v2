# Eval Suite — content-autopilot-v2

## Purpose

The eval suite tests the quality of LinkedIn posts generated by the P12/P12b
pipeline. It does not test correctness of DB writes or API contracts -- those
are integration tests. The eval suite checks:

- Post length (min/max characters)
- Absence of KI-signal words ("Als KI", "Ich hoffe", etc.)
- Presence of persona-specific signal words (e.g., "Klarheit", "Strategie")
- Question mark count (tone heuristic: max 2)
- Case-specific forbidden phrases

In mock mode the suite bypasses the LLM and DB and builds synthetic posts that
exercise the assertion logic. This is the default for CI (fast, no API costs).

In real mode the suite calls the actual pipeline, which requires a running
PostgreSQL instance, Celery worker, and valid Anthropic API key.

Pass threshold: 80% of cases must PASS for the suite to exit 0.

## Directory structure

```
backend/tests/eval/
  cases/
    <case_name>/
      transcript.txt          Synthetic onboarding transcript (~200 words, German)
      expected_features.json  Expected P01/P03/P04 features
      test_idea.json          Idea to generate a post from
      test_answers.json       3 entrepreneur answers
      quality_assertions.yaml Post quality rules
  mocks/
    __init__.py
    mock_anthropic.py         MockAnthropic client
    mock_db.py                MockSessionFactory for sync_session_factory
  run_eval.py                 CLI runner
  README.md                   This file
```

## How to add a new test case

1. Create a directory under `cases/` with the persona name (e.g., `julia_bauer`).
2. Add the following 5 files:

**transcript.txt**
Short synthetic onboarding transcript (~200 words, German). No real names or
real companies. All content must be fictitious.

**expected_features.json**
```json
{
  "p01": {
    "kernbotschaft": ["keyword1", "keyword2"],
    "zielgruppe": ["target_group_keyword"]
  },
  "p03": {
    "grundton": ["adjective1"],
    "signalwoerter": ["word1", "word2"]
  }
}
```

**test_idea.json**
```json
{
  "titel": "Idea title relevant to the persona",
  "beschreibung": "Brief idea description",
  "thema": "relevant topic"
}
```

**test_answers.json**
```json
[
  {"question_text": "Was ist dein persoenliches Learning aus diesem Thema?", "answer_text": "..."},
  {"question_text": "Welche konkrete Situation hat dich dazu gebracht?", "answer_text": "..."},
  {"question_text": "Was soll der Leser als naechsten Schritt tun?", "answer_text": "..."}
]
```

**quality_assertions.yaml**
```yaml
post:
  min_length: 300
  max_length: 3000
  required_signal_words:
    - "Word1"
    - "Word2"
  forbidden_words:
    - "Ich hoffe"
    - "Als KI"
    - "meiner Meinung nach"
    - "Fazit:"
    - "In diesem Beitrag"
    - "Zusammenfassend"
    - "uebrigens"
  max_question_marks: 2
  forbidden_phrases: []
```

Choose 2 signal words that are specific to the persona and should appear in
any well-generated post for that topic.

## How to run locally (mock mode)

From the `backend/` directory:

```
python tests/eval/run_eval.py --mock
```

This requires only `pyyaml` (no database, no Anthropic key).

Install pyyaml if needed:
```
pip install pyyaml
```

To run only specific cases:
```
python tests/eval/run_eval.py --mock --cases marcus_weber,lisa_hartmann
```

---

## How to run against the real LLM

Requires a running PostgreSQL instance, a valid Anthropic API key, and
a tenant with active voice/context/avatar profiles in the DB.

```
EVAL_TENANT_ID=<your-tenant-uuid> \
ANTHROPIC_API_KEY=<your-key> \
DATABASE_URL=postgresql://... \
python tests/eval/run_eval.py --real
```

The real pipeline calls Celery tasks via `.apply(...).get()` (eager mode),
so a running Celery worker is not required -- tasks run inline.

80% of cases must PASS for the runner to exit with code 0.

## Hinweis zum Mock-Modus

`--mock` mode tests the **assertion logic only**. It does NOT call the pipeline,
the LLM, or the database. `build_mock_post()` constructs a synthetic post that
is guaranteed to satisfy all assertions defined in `quality_assertions.yaml`.

The files `mocks/mock_anthropic.py` and `mocks/mock_db.py` are infrastructure
stubs for a future **semi-real** mode where the pipeline runs end-to-end but
with mocked backends (no real API calls, no real DB). They are not used by the
current `--mock` runner but are kept as documented infrastructure for that mode.

**When to use which mode:**

| Mode | When | What it tests |
|------|------|---------------|
| `--mock` | CI (every PR) | Assertion logic, YAML correctness |
| `--real` | Nightly (scheduled) | Actual LLM output quality |

Do NOT delete the mock files — they are intentional infrastructure stubs.
